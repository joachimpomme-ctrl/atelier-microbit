Ce projet a besoin d'une carte micro:bit V2 (logo doré sur la face avant).

Ta mission : le MiniCar et une voiture Wonder s'affrontent dans un cercle bordé de noir. Personne ne les pilote. Chacun cherche l'autre avec ses ultrasons et le pousse. Quand il voit le bord noir, il recule. Une carte arbitre lance le compte à rebours et arrête le combat.

Matériel : trois cartes. Le robot MiniCar (carte micro:bit V2, 3 piles AAA). Une voiture Wonder : la carte Wukong avec sa batterie, deux moteurs, le sonar:bit tourné vers l'avant et le double capteur de ligne tourné vers le sol. L'arbitre : une carte micro:bit avec un boîtier de piles (2 piles AAA) ou une batterie USB. L'arène : un grand cercle de ruban adhésif noir sur du papier blanc.

carte 1 : arbitrecarte 2 : MiniCarcarte 3 : voiture Wondermoteur → M1moteur → M2capteur de ligne → P1 et P2sonar:bit → une autre broche

La voiture Wonder mélange la voiture prudente et le suiveur de ligne. Le capteur de ligne prend P1 et P2 : branche le sonar:bit sur une autre broche libre, choisis-la dans le menu du bloc Ultrasonic distance in unit cm at pin …, et note-la.

Les blocs du MiniCar sont dans le tiroir de l'extension MiniCar. Pour l'ajouter : dans MakeCode, ouvre Extensions et colle l'adresse https://github.com/keyestudio2019/MiniCar. Ce que veut dire chaque chiffre de son capteur de ligne est dans ton carnet de la mission 8 de l'atelier robot.

Les deux robots n'ont pas le même poids : c'est un sumo pour rire. Tu peux lester le plus léger.

Choisis un numéro de groupe radio et écris-le sur un post-it collé sur chaque carte.

Sécurité : pas de chocs violents. Pour sortir un robot de l'arène, arrête d'abord ses moteurs.

Prédis d'abord

Ton robot pousse l'adversaire et arrive sur le bord noir : il voit les deux en même temps. Si ton programme s'occupe d'abord de l'adversaire, que va-t-il se passer ?

Ton cahier des charges

À remplir avant de coder. À la fin, la page te le rappelle pour vérifier.

1. Ton critère de réussite. Comment sauras-tu que c'est réussi ? Écris-le avec un nombre : une distance, un temps, ou un nombre d'essais réussis.

Exemple sur un autre cas, le dé électronique. Mauvais critère : « il marche bien », on ne peut pas le vérifier. Bon critère : « je le secoue 10 fois, il affiche 10 fois un nombre de 1 à 6 ».

2. Ton compromis. Ton robot attaque-t-il à fond ou à vitesse moyenne ?

Il n'y a pas de bonne réponse : ce qui compte, c'est ta raison. Tu pourras changer d'avis après les tests.

Le plan

  1. Rester dans l'arène : chaque robot, seul dans le cercle, avance. Quand un capteur de ligne voit le noir, il recule et tourne. Teste : reste-t-il dedans pendant une minute ?
  2. Chercher, puis foncer : le robot tourne sur place. Si l'adversaire est à moins de 40 cm, il fonce. Teste avec une boîte en carton à la place de l'adversaire.
  3. Tout ensemble : mets les deux règles dans un seul si … alors … sinon. Essaie les deux ordres : l'adversaire d'abord, puis le bord d'abord. Pousse la boîte vers le bord et compare.
  4. L'arbitre : il affiche 3, 2, 1, envoie « go », puis « stop » quand tu appuies sur un bouton. Les robots attendent le « go » et s'arrêtent au « stop ». Teste sans adversaire.
  5. Le match : les deux robots dans l'arène, l'arbitre lance. Après chaque manche, change une seule chose dans ta stratégie.

Noté.

Indice 1 · une question

Ton robot vit trois moments : il attend, il combat, c'est fini. Comment sait-il dans quel moment il est ?

Indice 2 · où chercher

Le tiroir Variables : une variable pour le moment du combat. Le tiroir Logique : si … alors … sinon, avec le petit + en bas du bloc pour ajouter des « sinon si ». Le tiroir Radio : le bloc qui réagit quand un texte arrive. Capteurs du MiniCar : les blocs du tiroir de l'extension MiniCar. Voiture Wonder : Ultrasonic distance in unit cm at pin … (tiroir sonar:bit) et le tiroir Broches pour le capteur de ligne.

Indice 3 · un exemple sur un autre cas

Au foot, l'arbitre siffle le début et la fin. Avant le premier coup de sifflet, les joueurs attendent. Après le dernier, ils s'arrêtent, même si le ballon roule encore.

La logique, en mots : l'arbitre, au bouton A, montre 3, 2, 1 avec une pause d'une seconde entre chaque, puis envoie « go ». Au bouton B, il envoie « stop ».

Chaque robot a une variable état, « attente » au départ. Quand « go » arrive : état = combat. Quand « stop » arrive : état = fin, moteurs arrêtés. Dans toujours, si l'état est combat : d'abord le bord (si un capteur voit le noir, reculer puis tourner un moment) ; sinon, si l'adversaire est à moins de 40 cm (sans compter le nombre qui veut dire « rien vu »), foncer ; sinon, tourner sur place pour chercher. Si l'état n'est pas combat : moteurs arrêtés. Le bord passe avant l'attaque, sinon le robot suit l'adversaire hors de l'arène. A et B ensemble : état = fin.
